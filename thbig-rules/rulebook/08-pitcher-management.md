## 8.0 概要

投手管理は「試合中の疲労」と「試合間の休養」の2層構造を持つ。

| 層 | フェーズ | 内容 |
|----|---------|------|
| 試合中 | Phase4_InGame | 疲労P超過による投球番号劣化・KO判定 |
| 試合間 | Phase5_PostGame〜Phase3_GameSetup | 中日数に基づく疲労P計算・負傷チェック |

**ゲームルールとLペナの境界**:
- 試合中の疲労（疲労P・KO条件）: 東方BIG野球本体のルール（thbig_baseball層）
- 休養計算・連戦制限: Lペナ（IRCリーグ）の大会運営ルール（lpena層）

## 8.1 投手区分の判定ロジック

投手の役割（先発/リリーフ/スラッシュ）は以下の優先順位で判定する。

```
INPUT: player_card, pitching_history

STEP 1: 直近登板履歴が存在するか確認
  IF 直近登板あり:
    → 直近登板の role（starter / reliever / opener）を使用
    → 以降の処理はそのroleに基づく

STEP 2: 履歴なし → カード属性で判定
  IF is_relief_only == true:
    → リリーフ（R付き選手は原則先発不可）
  ELSE:
    → 先発

スラッシュ選手の判定:
  starter_stamina IS NOT NULL
  AND relief_stamina IS NOT NULL
  AND is_relief_only == false
  → スラッシュ（先発・リリーフ兼任可能）

OUTPUT: role = "starter" | "reliever" | "opener"
```

## 8.2 試合中の疲労判定

### 8.2.1 基本疲労ルール

**疲労P未記載時のデフォルト値**（カードに疲労Pが記載されていない場合）:
- 先発投手: `3` として読み替え
- リリーフ投手: `0` として読み替え

```
INNING_FATIGUE_CHECK（各イニング終了時 or 交代時）:
  INPUT: pitcher.stamina, innings_pitched, runs_allowed

  # 基本: 投球イニング > 疲労P値で疲労状態
  is_fatigued = (innings_pitched > pitcher.stamina)

  # 5イニング以上無失点特例
  IF innings_pitched >= 5 AND runs_allowed == 0:
    is_fatigued = false  # 疲労状態も解除
    # 例外1: 10回以降はランナーを出すと疲労
    # 例外2: 11回以降は最初から疲労状態

  # 疲労P猶予
  IF 前イニングで疲労P回数を投げた:
    敬遠以外のランナーを出すまで is_fatigued = false

OUTPUT: is_fatigued (bool)
```

> **⚠️ 訂正（2026-10-25・Operator裁定）— 疲労P 0 と「最初から疲労状態」は別の状態**
> 本章には「疲労P 0」（§8.3 の各表）と「最初から疲労状態」（§8.3.2 の累積2イニング以上）の両方が出てくるが、
> 両者の効果の違いはどこにも書かれていなかった。上記疑似コードでは、疲労P 0 なら登板直後から `is_fatigued` が真になり、
> 「最初から疲労状態」と区別がつかない。
>
> 本裁定で決着した。
>
> | 状態 | 疲労するタイミング |
> |---|---|
> | 疲労P 0 | 最初の出塁を許す（申告敬遠による出塁は数えない）か、2イニング目に入るか、**どちらか早い方**で疲労状態になる |
> | 最初から疲労状態 | 登板の最初の打者から疲労状態 |
>
> 疲労P 0 の扱いは、上記の「疲労P猶予」（前イニングで疲労P回数を投げた → 敬遠以外のランナーを出すまで疲労しない）を、
> 疲労P 0 で登板した場合に当てはめた形と同じになる。猶予は最初のイニングに限られ、2イニング目に入れば `innings_pitched > 0` で疲労状態になる。
> この対応づけは書き手の整理として示し、Operator が「その理解で合ってる」と確認した（2026-10-25）。
>
> ```
> 登板時の初期状態:
>   IF 最初から疲労状態（§8.3.2 累積2イニング以上 等）:
>     is_fatigued = true                      # 最初の打者から
>   ELSE IF 補正後の疲労P == 0:
>     is_fatigued = false
>     # 次のどちらか早い方で true:
>     #   - 申告敬遠以外の最初の出塁を許した時点
>     #   - 2イニング目に入った時点
> ```
>
> 理由: 裁定時に Operator からの説明は無い。
>
> 詳細・裁定根拠: `context/thbig-bench-rule-adjudications.md`（multi-agent-shogun リポジトリ）

### 8.2.2 疲労状態の効果

疲労状態（is_fatigued=true）の投手は、投球番号決定時に「*マーク付き」行の投球番号が劣化する。

```
FATIGUE_DEGRADATION（*マーク付き行に限る）:
  2 → 1
  3 → 2
  5 → 4
  ※ 1と4には*マークが付かないため劣化なし
```

### 8.2.3 KO判定

```
KO_CALCULATION:
  INPUT:
    role: str                # "starter"
    innings_pitched: float   # 例: 4.67（4回2/3）
    game_result: str         # "lose"
    pitchers_in_game: int    # この試合での同チーム投手総数
    decision: str            # "L"（負け投手）

  KO_THRESHOLD = 5  # game_rules.yaml: thbig_baseball.game.ko_innings_threshold.value

  ko = (
    role == "starter"
    AND innings_pitched > 0
    AND innings_pitched < KO_THRESHOLD  # 4回2/3以下
    AND pitchers_in_game > 1            # 後続投手あり
    AND game_result == "lose"
    AND decision == "L"                 # 負け投手
  )

OUTPUT: result_category = "ko" | "normal" | "long_loss" | "no_game"

result_category判定順序（Dugout: PitcherGameState#calculate_result_category）:
  1. game_result == "no_game" → "no_game"
  2. role != "starter" → "normal"
  3. KO条件に該当 → "ko"
  4. 長イニング敗戦条件に該当 → "long_loss"
  5. それ以外 → "normal"

長イニング敗戦条件:
  game_result == "lose"
  AND innings_pitched > pitcher.stamina + 1  # 疲労P + 1イニング超過
```

> **⚠️ 訂正（2026-10-25・Operator裁定）— KO判定には0アウト降板の+1を掛けない**
> 上記疑似コードは、KO 条件と長イニング敗戦条件の両方に同じ `innings_pitched` を使っている。
> §8.2.4 の適用範囲表は KO を挙げていないが、変数が同じであるため、§8.2.4 の関与イニング数（0アウト降板で+1）を
> KO にも掛ける読みが文面から排除できなかった。
>
> **KO 判定には0アウト降板の+1を掛けない。** KO の `innings_pitched` は実際に投げた投球回（上記の例 4.67 = 4回2/3 の形）で判定する。
> +1 は長イニング敗戦側の関与イニング数にだけ使う。
>
> 具体例: 4回を投げ終え、5回の頭から1アウトも取れずに降板した先発（敗戦投手・後続投手あり）。
> 投球回 4.0 < 5 なので **KO**。関与イニング数（4 + 1 = 5）で判定すると KO から外れるが、その読みは採らない。
>
> 理由: 裁定時に Operator からの説明は無い。§8.2.4 の適用範囲表（KO を含まない）とは一致する。
>
> 詳細・裁定根拠: `context/thbig-bench-rule-adjudications.md`（multi-agent-shogun リポジトリ）

>

> 疑似コードの `innings_pitched > 0` は「登板した」の意味で読む。+1 を掛けない原則は変わらない。
> 境界: 4.0回＋0アウト降板 → KO、4.2回 → KO、0.0回＋0アウト降板 → KO。6イニング目のマウンドに上がっていた（投球回 5.0）なら、0アウト降板でも KO は付かない（5.0 < 5 を満たさない）。

### 8.2.4 投球イニングの数え方（関与イニング数）

長イニング敗戦判定（8.2.3 の `innings_pitched`）や累積イニング加算（8.3.2）で使う
「関与イニング数」の計算方法。

**計算式（通算アウト数ベース）:**

```
prior_outs = 前投手までの通算アウト数
my_outs    = この投手が取ったアウト数

start_inning = floor(prior_outs / 3) + 1
end_inning   = floor((prior_outs + my_outs - 1) / 3) + 1
関与イニング数 = (end_inning - start_inning + 1) + (no_out_exit ? 1 : 0)

※ my_outs=0（0アウト降板）の場合は関与イニング数=1
```

- **通算アウト数**: 試合開始からの通算アウト数で、投手が何回目に登板し何回目まで投げたかを正確に算出する
- **no_out_exit（0アウト降板フラグ）**: 回の頭から投げて打者を1人も抑えずに降板した場合 `true`。次の回に跨いだ扱いとして+1する
- **my_outs=0 の場合**: 0アウト降板でも登板した時点で最低1イニング関与として扱う

**適用範囲:**

| 判定 | 使用箇所 |
|------|---------|
| 長イニング敗戦（先発） | 先発投手の登板イニング数が長イニング敗戦の閾値に達したか判定（→8.2.3） |
| 累積イニング加算（リリーフ） | リリーフ1回の登板で累積に加算するイニング数（→8.3.2） |

## 8.3 投手休養ルール（試合間）

### 8.3.1 先発→先発

**前提**: 中2日以内は登板不可（疲労P計算以前に登録不可）

#### 通常（result_category = "normal"）

| 中日数 | 疲労P | 負傷チェック |
|--------|-------|------------|
| 中2日以内 | **登板不可** | — |
| 中3日 | 0 | **発動** |
| 中4日 | −3 | 2回連続で**発動** |
| 中5日 | −1 | なし |
| 中6日以上 | カード記載疲労P | なし |

#### KO・ノーゲーム時（result_category = "ko" または "no_game"）

| 中日数 | 疲労P | 負傷チェック |
|--------|-------|------------|
| 中2日以内 | **登板不可** | — |
| 中3日 | −3 | なし |
| 中4日 | カード記載疲労P | 2回連続で**発動** |
| 中5日以上 | カード記載疲労P | なし |

→ 通常より**2日短縮**（中4日〜がカード値で登板可）

#### 長イニング敗戦時（result_category = "long_loss"）

| 中日数 | 疲労P | 負傷チェック |
|--------|-------|------------|
| 中2日以内 | **登板不可** | — |
| 中3日 | 0 | **発動** |
| 中4日 | −4 | 2回連続で**発動** |
| 中5日 | −2 | なし |
| 中6日 | −1 | なし |
| 中7日以上 | カード記載疲労P | なし |

→ 通常より**1日延長**（中7日〜がカード値）

> **⚠️ 訂正（2026-10-25・Operator裁定）— 長イニング敗戦は試合に負けた時のみ。敗戦投手は条件にしない**
> 出典の sources §1-b（KO: 「4回2/3以下で敗戦」）と §1-c（長イニング: 「…超過で敗戦した場合」）は、同じ「敗戦」の語を使っている。
> §8.2.3 は KO にだけ `decision == "L"`（負け投手）を課し、長イニング敗戦には課していない。
> ただし同じ語を読み分ける根拠がどこにも書かれていなかったため、長イニング敗戦も敗戦投手に限る読みが残っていた。
>
> **長イニング敗戦は、チームが試合に負けた時のみ適用する。** その先発が敗戦投手（L）かどうかは問わない。

>
> §8.2.3 の長イニング敗戦条件（`game_result == "lose"` のみで `decision` を含まない）は本裁定と一致しており、文面の変更は無い。

>

### 8.3.2 リリーフ→リリーフ（累積イニング管理）

#### 累積イニング加算・減衰

```
RELIEF_INNINGS_MANAGEMENT:

【加算】
  登板したイニング数をカウント（出てきたイニング数の合計）
  例: 6回途中から登板し8回途中まで投げた場合 = 累積 +3I（6回・7回・8回の3イニング）
  ※ 1イニング内のみで交代した場合は +1I

【減衰】（登板しなかった日ごと）
  IF accumulated_innings <= 3:
    accumulated_innings -= 2  # 下限: 0
  ELSE:  # accumulated_innings >= 4
    accumulated_innings -= 1  # 下限: 0

  MIN = 0（マイナスにはならない）
```

#### 登板時の疲労P計算

| 累積イニング数 | 疲労P |
|--------------|-------|
| 0 | カード記載疲労P |
| 1 | 0 |
| 2以上 | 最初から疲労状態 |

> **⚠️ 訂正（2026-10-25・Operator裁定）— 累積2イニングでの登板は、最初から疲労状態**

> この注により、累積2イニングを累積1と同じ疲労P 0 として扱う読みが残っていた。
>
> 本裁定は表の文面を採る。**累積2イニングでの登板は、登板の最初から疲労状態として扱う。** 疲労P 0 相当とはみなさない。
>
> 裁定が明示したのは累積2イニングである。3以上は上表の「2以上」の行に含まれ、文面上は同じ扱いになる（個別には裁定していない）。
> 「疲労P 0」と「最初から疲労状態」は別の状態である（同日の追補裁定）。違いは §8.2.1 の 2026-10-25 訂正を参照。

> ELSE IF rest_days == 5:  accumulated_innings = MIN(accumulated_innings, 1)   # 疲労P 0 まで
> ```
>
> 例: 累積8 は、減衰だけでは5日休んで累積3（最初から疲労状態）、6日休んで累積1（疲労P 0）。上限により5日で疲労P 0、6日でカード記載疲労P になる。
> 累積7 までは、減衰だけで上限と同じ結果になる。
>
> 退けた読み: 「中5日ちょうどなら累積に関係なく疲労P 0」（参考実装 `matome-ods/tools/pitcher_rest.py` の読み）。
> 累積0 の救援が、中1日ではカード記載疲労Pなのに、中5日では疲労P 0 に悪化してしまうため採らない。
>
> 留保: 上限としての読みは wiki に明記が無く、原文と計算からの推定である。Operator が別の趣旨を示せば改める。
> 裁定の種別: **本体判断**（Operator は 2026-10-26 に「なにか混ざってそう」と精査を指示し、結果に対して「それで進めて」と採否を本体に委ねた）。
> Operator が個別に裁定した読みではない。
>
> 詳細・裁定根拠: `context/thbig-bench-rule-adjudications.md`（multi-agent-shogun リポジトリ）AMB-21 節、
> `context/thbig-rules-relief-5day-recovery-origin.md`（出どころ調査）

## 8.5 負傷チェック（投手休養起因）

### 8.5.1 発動条件一覧

| # | 条件 | 状況 |
|---|------|------|
| 1 | 先発: 疲労P 0での先発登板 | 中3日先発 / 長イニング後中3日先発 |
| 2 | 先発: 2回連続での中4日先発 | consecutive_short_rest_count >= 1 の中4日先発 |
| 3 | リリーフ: 累積3イニング以上での登板 | accumulated_innings >= 3（登板時点の累積） |
| 4 | オープナー: 中2日以内の連続登板 / 前日登板 / 累積1イニング以上 | — |

> **⚠️ 訂正（2026-10-26・Operator裁定）— 条件 2 の「連続」は、起点の登板以降がすべて先発登板の時だけ。間隔は中4日「以下」**
> 条件 2（`consecutive_short_rest_count >= 1`）が成り立つのは、**連続する 3 回の先発登板で、その間隔が両方とも中4日以下**の場合である。
> 間にリリーフ登板（オープナー登板を含む。§8.4.2 でリリーフ扱い）が 1 度でも入れば連続は切れ、カウントは 0 に戻る。
> 第二先発候補の 2 番手登板は §8.4.2 で先発扱いなので、連続を切らない。
>
> 数え方の変更点（旧: 直前の**先発**登板との中日数が中4日ちょうどなら +1）:
>
> - 見るのは**直前の登板**（役割を問わない）。直前の登板がリリーフ・オープナーなら、その前に先発があってもカウントは 0
> - 直前の登板が先発で、そこからの中日数（離脱を差し引いた値）が**中4日以下**なら前回値 + 1。中5日以上なら 0。中3日も数える（中2日以内は先発不可なので現れない）
> - 実日数差の中10日リセット（§8.6）が成立する時は 0（他の判定より先に見る）
>
> ```
> 連続中4日以下先発のカウントの更新:
>   last = 直前の登板（役割を問わない）
>   IF last が無い OR last.role != "starter": consecutive_short_rest_count = 0
>   ELSE IF (next_game_date - last_game_date) - 1 >= 10: consecutive_short_rest_count = 0   # 中10日リセット
>   ELSE IF 離脱を差し引いた rest_days <= 4: consecutive_short_rest_count = last.consecutive_short_rest_count + 1
>   ELSE: consecutive_short_rest_count = 0
> ```
>
> 負傷チェックの発動（条件 2）: 今回の先発が中3日または中4日で、直前の先発のカウントが 1 以上（＝その前の間隔も中4日以下）の時。
> 例: 先発 → 中3日 → 先発 → 中4日 → 先発 / 先発 → 中4日 → 先発 → 中3日 → 先発 は、どちらも 3 回目で発動（カウントは 0, 1, 2）。
> 先発 → 中5日 → 先発 → 中4日 → 先発 は発動しない（カウントは 0, 0, 1）。
> 中3日の先発は、通常・長イニング敗戦なら条件 1（疲労P 0）でもそれ自体が負傷チェックになる。カウントは条件 2 のために別に数える。
> §8.3.1 の KO・ノーゲーム中3日（表では「なし」）も、カウントが 1 以上なら条件 2 で発動する（本注記の適用範囲の読み。Operator の言は先発の種別を分けていない）。
>
> §8.6 の 2026-10-26 注記（中10日リセットは連続中4日のカウントも 0 に戻す）内の疑似コードの `rest_days == 4` は、本注記により `rest_days <= 4` と読む。

### 8.5.2 判定

**判定タイミング**: 試合終了時（登板中ではなく試合後に実施）
**判定基準**: 試合終了時の累積イニング数

⚠️ **発動条件と判定基準は別概念**:
- 発動条件（条件3）: 累積3I以上で「登板した」かどうか（試合開始前の累積値で判定）
- 判定基準: 試合終了時点の累積イニング数（当該試合分を加算した後の値）

**なぜテーブルに「累積3I」行がないか**:
累積3Iで登板した場合、最低1I投げるため試合終了時には累積4I以上になる。
よって試合終了時の累積が3Iになるケースは発生しない。

```
INJURY_CHECK:
  INPUT: trigger_condition (上記1〜4のいずれか), accumulated_innings_at_game_end (リリーフのみ)

  STEP 1: けが特徴レベルの決定（リリーフ: 試合終了時の累積イニング数で判定）
    IF trigger_condition == リリーフ（累積3I以上で登板）:
      試合終了時累積4I  → けが特徴5
      試合終了時累積5I  → けが特徴4
      試合終了時累積6I  → けが特徴3
      試合終了時累積7I以上 → けが特徴2
    ELSE:  # 先発・オープナー
      → けが特徴2

  STEP 2: 1d20をロール
  STEP 3:
    IF dice_roll <= 6:
      → 負傷（STEP 1で決定したけが特徴レベルで怪我チェックへ）
    ELSE:
      → 安全（通常通り登板）

  → 怪我チェックの詳細: 10-injuries-and-traits.md
```

**Dugout実装**: `pitcher_game_state.injury_check` カラム（"safe" / "injured"）

## 8.6 負傷離脱中の扱い

```
INJURY_ABSENCE_RULES:

  # 中日数カウントに離脱期間を含めない
  rest_days = 実際の試合日数差 - absence_days

  # 10日（離脱除外）空ければ疲労なしで登板可能
  IF rest_days >= 10:
    fatigue_p = card_stamina  # カード記載値で登板可能

  # 離脱中の累積イニング管理
  離脱中は減衰も凍結（cumulated_inningsはそのまま保持、減衰しない）
  復帰後も負傷前の累積イニングが残った状態で登板する

  # 中10日でリセット
  IF rest_days >= 10:  # 疲労Pがカード値に戻るタイミングと同じ
    accumulated_innings = 0  # 累積イニングも0にリセット
```

> **⚠️ 訂正（2026-09-12・Operator裁定）**
> 上記の「実際の試合日数差」は、**試合日の個数**とも**試合日の日付の差**とも読めてしまう。
> 本裁定は後者を採る。「日」は**ゲーム内カレンダーの日**（休養日・移動日を含む区間の日数）であり、
> 試合日の個数ではない。正しい形は §8.7.2 の `(next_game_date - last_game_date) - 1` であり、
> 上記の「実際の試合日数差」は「実際の試合日（＝登板日）**の日付の差**」と読み替える。
>
> `absence_days` は**負傷離脱の日数**である。**出場停止（ペナルティ）は別枠**で、中日数計算には
> 干渉しない。出場停止は試合日換算・負傷離脱は日数換算であり、単位が異なるため一方をもう一方へ
> 換算して合算しない。同一選手に負傷離脱と出場停止が同時に成立しうるが、それぞれ独立に計数する。
>
> 下限は0に丸める（同一日に複数登板した場合に負値になるため）。
>
> 具体例: 9/1登板 → 9/2休養日 → 9/3試合 → 9/4移動日 → 9/5登板 は `(5-1)-1 = 3` で**中3日**。
>
> 詳細・裁定根拠: `context/thbig-bench-rule-adjudications.md`（multi-agent-shogun リポジトリ）
> AMB-04 節・境界-1 節（Operator裁定 2026-09-12）

> **⚠️ 訂正（2026-09-13・Operator裁定）— リセット判定に離脱期間は関与しない**
> 上記疑似コードは `rest_days`（= 実際の試合日数差 − `absence_days`）を、疲労Pの復帰と
> 累積イニングのリセットの**両方**に掛けているが、**リセット判定については誤り**である。
>
> **中10日で疲労がリセットされる判定に、離脱期間は関係しない。** 実日数差
> `(next_game_date - last_game_date) - 1` で中10日が経過すれば、離脱の有無・長短にかかわらず、
> どの場合も `fatigue_p = card_stamina` に戻り `accumulated_innings = 0` にリセットされる。
>
> **理由**（Operator）: 2軍に落として最短で戻してきた時に疲労が残っているとゲームとして困る。
> §3 の1軍⇔2軍移動はクールダウン10日であり、最短復帰がちょうど中10日にあたる。リセット判定から
> 離脱日数を差し引くと、「負傷で離脱 → 2軍へ降格 → 最短で戻す」経路で**必ず疲労を持ったまま復帰する**
> ことになる。
>
> したがって本節の「中日数」は用途によって2種類ある。取り違えないこと。
>
> | 用途 | 使う中日数 |
> |---|---|
> | 累積イニングの日々の減衰（離脱中は凍結） | 離脱を差し引いた `rest_days` |
> | 先発の登板可否（§8.3.1・中2日以内は不可） | 離脱を差し引いた `rest_days` |
> | **疲労Pの復帰・累積イニングのリセット** | **差し引かない実日数差** |
>
> 帰結として、離脱が10日以上続いた場合は「離脱中は減衰凍結」が実質意味を持たない（実日数差が
> 10日に届いた時点でリセットされ累積イニングが0になるため）。減衰凍結が効くのは、離脱が明けても
> なお中10日に届かない区間に限られる。両者は矛盾しない。
>
> 詳細・裁定根拠: `context/thbig-bench-rule-adjudications.md`（multi-agent-shogun リポジトリ）
> 「AMB-04 追補: 中10日リセットに離脱期間は関与しない」節（Operator裁定 2026-09-13）

> **⚠️ 訂正（2026-10-25・Operator裁定）— 中10日リセットが成立する時は、登板可否より優先する**
> 2026-09-13 訂正の表は、先発の登板可否（中2日以内は不可）には離脱を差し引いた `rest_days` を、
> リセットには差し引かない実日数差を使うと定めた。
> 両者が食い違う場合、すなわち実日数差では中10日に届いているのに、離脱を差し引くと中2日以内になる場合に、
> どちらを採るかは書かれていなかった。
>
> **実日数差で中10日リセットが成立する時は、離脱を差し引いた中日数が2日以内でも登板できる。** 中10日リセットを優先する。
> 疲労Pはカード値、累積イニングは0の状態で登板する。上表の「先発の登板可否」行は、リセットが成立しない場合に限って読む。
>
> ```
> 先発の登板可否:
>   IF (next_game_date - last_game_date) - 1 >= 10:   # 実日数差。離脱を差し引かない
>     → 登板可（中10日リセット）
>   ELSE IF 離脱を差し引いた rest_days <= 2:
>     → 登板不可
> ```
>
> 具体例: 10/1 登板 → 10/2〜10/11 負傷離脱（10日）→ 10/12 先発。
> 実日数差は `(12 - 1) - 1 = 10` で中10日、離脱を差し引くと0日。リセットが成立するので登板できる。
>
> 理由: 2026-09-13 裁定（リセット判定に離脱期間は関与しない）の続きとして Operator が示した。
> 09-13 の理由（2軍へ落として最短で戻した投手に疲労を残さない）は、リセットが成立しても登板不可が残るなら意味を失う。
> この整理は本注記の書き手によるもので、Operator の説明ではない。
>
> 詳細・裁定根拠: `context/thbig-bench-rule-adjudications.md`（multi-agent-shogun リポジトリ）
> 「AMB-04 追補 2: 中10日リセットは登板可否より優先する」節（Operator裁定 2026-10-25）

> **⚠️ 訂正（2026-10-26・Operator裁定）— 中10日リセットは、連続中4日先発のカウントも 0 に戻す**
> 実日数差 `(next_game_date - last_game_date) - 1 >= 10` で中10日リセットが成立する時は、疲労に関わる情報がすべてリセットされる。
> 疲労Pはカード値、累積イニングは0（2026-09-13 の訂正）に加えて、**連続中4日先発のカウント（`consecutive_short_rest_count`、§8.5.1 条件2）も 0 に戻る**。
> 離脱を差し引いた中日数がちょうど中4日になる場合も、連続中4日には数えない（カウントを前回値 +1 にしない）。
>
> ```
> 連続中4日先発のカウントの更新:
>   IF (next_game_date - last_game_date) - 1 >= 10:   # 実日数差。離脱を差し引かない。他の判定より先に見る
>     consecutive_short_rest_count = 0                 # 中10日リセット
>   ELSE IF 離脱を差し引いた rest_days == 4:
>     consecutive_short_rest_count = 前回値 + 1
>   ELSE:
>     consecutive_short_rest_count = 0
> ```
>
> 具体例: 6/1 先発 → 6/2〜6/7 負傷離脱（6日）→ 6/12 先発。実日数差は `(12 - 1) - 1 = 10` でリセットが成立する。
> 離脱を差し引くとちょうど中4日（`10 - 6 = 4`）だが、連続中4日にはならず、カウントは 0。
>
> Operator の言（2026-10-26）:「中１０日はすべての疲労関連の情報がリセットされるから、その場合も連続中４にはならない」。
> 発端は cmd_1775 第2段の QC が、「実日数10日以上・離脱を差し引くとちょうど中4日」の組合せでカウントが +1 になる実装を、明文が無い点として挙げたこと。
>
> 詳細・裁定根拠: `context/thbig-bench-rule-adjudications.md`（multi-agent-shogun リポジトリ）
> 「AMB-04 追補 3: 中10日リセットは連続中4日のカウントも消す」節（Operator裁定 2026-10-26）

## 8.7 投手管理の完全フロー

### 8.7.1 試合後（Phase5_PostGame）

```
POST_GAME_PITCHER_FLOW:
  FOREACH pitcher in game.pitchers:
    1. result_category を計算（§8.2.3）
    2. 疲労P の記録
    3. 連続中4日先発カウントの更新（consecutive_short_rest_count）
    4. 累積イニングの更新（リリーフの場合）
    5. 負傷チェック実施（条件該当時、§8.5）
    6. pitcher_game_state に保存
```

### 8.7.2 次試合予告先発時（Phase3_GameSetup）

```
PRE_GAME_PITCHER_VALIDATION:
  INPUT: pitcher, next_game_date, last_game_state

  STEP 1: 中日数を計算
    rest_days = (next_game_date - last_game_date) - 1
    有効中日数 = rest_days - absence_days（離脱期間を除外）

  STEP 2: 登板可否判定
    IF role == "starter" AND effective_rest_days <= 2:
      → 登板不可（エラー）
    IF role == "reliever":
      → 登板不可制限なし（中0日=連投も可能）
        累積イニング管理で疲労は蓄積するが、登板自体に日数制限はない

  STEP 3: 疲労P計算
    → §8.3の対応テーブルを参照

  STEP 4: 負傷チェック発動判定
    → §8.5の条件確認

  OUTPUT: fatigue_p, injury_check_required
```

> **⚠️ 訂正（2026-10-25・Operator裁定）**: STEP 2 の先発の登板不可判定より先に、`rest_days >= 10`（離脱を差し引かない実日数差。
> 中10日リセット）を見る。成立すれば `effective_rest_days` が2日以内でも登板可とする。詳細は §8.6 の 2026-10-25 訂正。

## 8.8 精神疲労ルール

⚠️ **「精神疲労」は2つの別概念**:

| 概念 | 種別 | 定義 | 現在の該当 |
|------|------|------|-----------|
| 投手特徴「精神疲労」 | カード記載の選手特徴 | 失点した時点で疲労状態になる（通常は一定投球数で疲労するが、失点で即疲労） | 現在該当なし |
| 精神疲労ルール | 全投手共通のルールメカニクス | 累積10失点/15失点で発動する試合後処理 | 全投手に適用 |

- 選手特徴「精神疲労」は01-players-and-cards.md §1.13の特徴表に記載
- 精神疲労ルール（以下）は選手特徴と無関係に、全投手に適用される

**閾値の対象**（欠落の補充・2026-09-12 Operator裁定）:

- 精神疲労（10失点）・精神崩壊（15失点）とも、閾値は**投手個人**の失点（非自責を含む）に掛かる。
  チームの被失点合計を集計するルールではない
- 「全ての投手が」は**対象範囲の説明**（特徴の有無に関わらず全投手が対象になる、という意味）であり、
  閾値の主語ではない
- 理由: 打ち込まれた投手をそのまま続投させてリリーフ投手の消耗を防ぐ戦術を抑止するためのルールであり、
  閾値がチーム合計に掛かると個人の打ち込まれ具合と無関係に発動してしまい機能しない
- 精神疲労由来の`long_loss`上書き（先発投手の追加ペナルティ）は、§8.2.3の通常の`result_category`
  判定順序（no_game → 非先発はnormal → ko → long_loss → normal）とは**別に持つ**。判定順序そのものは
  入れ替えない（一般のKO判定と精神疲労由来のペナルティを混同しない）

```
MENTAL_FATIGUE_RULE:

  # 精神疲労（10失点）
  MENTAL_FATIGUE:
    発動条件: 全ての投手が10失点（非自責を含む）した場合
    効果: イニング数に関わらず疲労状態（fatigue_p = 0）となる

    先発投手の追加ペナルティ:
      精神疲労した次のイニングも投げた場合
      → result_category = "long_loss"（長いイニングを投げて敗戦）扱い
      → 次登板の回復に中7日を要する（§8.3.1 長イニング敗戦ルール適用）

      ※ KO敗戦と重複した場合: "long_loss" が優先

  # 精神崩壊（15失点）
  MENTAL_COLLAPSE:
    発動条件: 全ての投手が15失点（非自責を含む）した場合
    効果: 試合終了時に負傷チェックを行う

    負傷チェック:
      1d20 を実行
      6以下 → 負傷確定
      7以上 → 負傷なし

      負傷確定時:
        → けが特徴2でけがチェック（§9章 負傷判定プロトコル）

      ⚠️ この負傷は特例（§3.7 特例選手ルール）でも回避不可

    先発投手の追加ペナルティ（負傷回避時も適用）:
      → result_category = "long_loss" 扱い（中7日回復）

    中継ぎ投手の追加ペナルティ:
      → 累積イニング + 4 を追加

  # 救済措置（精神疲労状態の投手が降板した試合中）
  MENTAL_FATIGUE_RELIEF:
    適用条件:
      - 精神疲労状態（10失点以上）の投手が降板した試合中
      - 登板する投手が「累積イニング0」かつ「コスト1」の選手

    効果:
      → 本来の疲労P より +2イニング分疲労せずに登板できる
      （累積イニングの計算は通常通り行う）

    例:
      疲労P=1R の投手 → 3Rまで疲労なし
      4イニング目に走者を出すと疲労、5イニング目から疲労状態

    ※ 例外: 天弓千亦（固有名）もこのルール適用可（コスト制限なし）
```

> 出典: https://thbigbaseball.wiki.fc2.com/wiki/追加ルール
> 欠落補充: `context/thbig-bench-rule-adjudications.md`（multi-agent-shogun リポジトリ）AMB-05 節・境界-2 節
