# カード画像の読み直し結果（核）

`card_reread_2026-11-13.json` は、東方BIG野球の選手カード 432 枚（card_seq 1〜432）を画像から読み直した結果のうち、
どのカードでも形がそろっている部分（核）だけを正規化して 1 ファイルにしたもの。CSV を画像に合わせて直す時の入力に使う。

## 出どころ

- 読み直し: 2026-11-13、各カードの画像を今のモデルで読み直した（読み手はカードの組ごとに別）。元の JSON 432 枚は `tmp/card_reread/{card_seq}.json`（gitignore 対象で残らない）。
- 照合の基準: origin/main `1f4989e` の `db/import/` の 4 CSV。
- 照合結果と直し方の分類: 画像読み直しの全体集約（ハーネス側 `context/thbig-card-data-reread-all.md`）の §2〜§3。
- この核を正として CSV を直した範囲は、同文書 §3.2 の (A)（cmd_1888）。(B) と、331・332・339 は直していない。

## 中身

card_seq（文字列）をキーに 1 カード 1 行のオブジェクト。

| キー | 内容 |
|---|---|
| name / number / position | 画像の名前・背番号・位置（`内野手` `投手` `横綱` など画像の表記のまま） |
| throwing_hand / batting_hand | `right` `left` / `right` `left` `switch`（CSV の語彙。画像の「右投両打」は `right` / `switch`） |
| speed / bunt / steal_start / steal_end | 走力・バント・盗塁スタート・盗塁エンド |
| defense | `{position, range, error_rank, throwing}` の配列（throwing は肩。画像が空なら `null`） |
| fatigue | 疲労 P。`{starter, relief, relief_only, closer}`。無ければ `null`。`relief_only` は画像の R、`closer` は画像の C |
| batting_table | 打撃表 20 行（各行 4 または 5 列の文字列） |
| pitching_table | 投球表 20 マスの文字列配列。投手欄が無いカードは `null` |
| injury_rate | けがレベル。読み直しで拾えなかったカードは `null`（432 枚中 164 枚。CSV の値を使うこと） |

特徴・能力欄・特例起用・条件付き特徴・注記は核に含めていない（組ごとに持ち方が違い、正規化できなかった）。それらは文書の表を正とする。

## 空欄の正規化

元の JSON は空欄を `''` `null` `-` の 3 通りで書いていた。核では打撃表の空欄をすべて `''`（空文字）に統一した。
該当は二刀流の打撃表 5 列目（20・240・388・389・402・403・413・419）で、CSV は同じ位置を `K` で埋めている（表現差。直していない）。
疲労 P と投球表の「無い」は `null`。キーの揺れ（`hands` / `traits` / `traits_text` / `abilities` など）は核に持ち込んでいない。

## 注意

- CSV を見て直した値が混じっている。読み手の転記ミスを CSV との照合で見つけて画像で直したもの（363・372・408・421・425・426・428、走力・バントの取り違えの 271・283）。いずれも CSV が正しく、画像とも一致する。
- 疲労 P の単独数字（11・145・184・402・403・419 など、先発の欄に 1〜3 が入る形）は核に画像の数字のまま入っている。ルールブックの範囲規則（0〜3 は救援、4〜9 は先発）では CSV が正しいので、核を CSV に写す時は規則を通すこと。
- 画像から直接読んだのは読み手で、核の値の確度はカードごとに違う（読み手が拡大して確かめたものは文書に記載）。
- 317・319 の `name` は画像どおり（`おくでら まさし`・`植田`）。CSV の 319 は PM2026 に同名の 304 がいるため `植田 (2)` と区別して持つ。
